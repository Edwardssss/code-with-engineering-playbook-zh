# ISE 工程基础手册

在 [ISE](ise.md) 项目上工作的工程师……

* 对团队负有责任 —— 做导师、做教练、做领路人。
* 了解自己的**手册**，遵循它。手册坏了就修好它。找到更好的手册就抄过来。别人用得上自己的手册就分享出去。
* 以身作则。在人际与技术两方面都做出我们期望的行为示范。
* 努力理解自己的工作如何嵌入更大的图景，并确保最终结果。

这是我们的手册。欢迎任何形式的贡献！直接提一个 pull request 就可以参与进来。

## 为什么要有一本手册

* 提升团队成员乃至整个团队的总体效率。
* 减少错误、避开常见的坑。
* 努力成为更好的工程师，从他人分享的经验中学习。

如果其他什么都做不到，至少照着[工程基础检查清单](./engineering-fundamentals-checklist.md)执行。

[ISE 项目的第一周](./the-first-week-of-an-ise-project.md)按 Agile 冲刺的结构，把手册的各个部分拆解了一遍。

## 通用指引

* 保持高代码质量门槛。
* 重视质量与精确，而不是「把事情做完」。
* 踏踏实实做好那件最重要的事。
* 作为分布式团队，花时间通过 wiki、Teams 和待办项共享上下文。
* 先让简单的东西跑起来。今天少做几个功能，但保证它们运转得足够出色，明天再加更多功能。
* 不要往待办项里塞新的范围，而是新建一个待办项。
* 我们的目标是持续交付客户价值。
* 待办项的细节要保持最新，以便与团队其他人同步事情的进展。
* 报告发现的产品问题，并给出清晰、可复现的工程反馈！
* 代码是我们共有的，每个人都有义务让解决方案的每个部分都足够好。
